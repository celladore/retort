## Goal

Add an 11th team (`cli`) with a dedicated `cli-engineer` agent to own CLI entry points, npm packaging, distribution pipelines, and engine module boundaries.

## Assumptions & Constraints

- The current 10-team structure has no owner for `bin/`, `src/cli*`, `engines/**`, or publish scripts
- Scope overlaps with `devops` (CI publish workflows) and `platform` (engine internals) — resolution rules are defined below
- The short team ID `cli` follows the existing single-word convention (`backend`, `frontend`, `devops`, etc.)

## Proposed Approach

1. Add `cli` team to `.agentkit/spec/teams.yaml` (after `quality`)
2. Add `cli-engineer` agent to `.agentkit/spec/agents.yaml` (under `engineering` category)
3. Run `agentkit sync` to generate `/team-cli` command, `cli-engineer.agent.md`, `team-cli.chatmode.md`
4. Update `UNIFIED_AGENT_TEAMS.md` with T11 row + full definition
5. Update `orchestrator.mjs` to include `team-cli` in the team registry
6. Add T11-CLI items to `AGENT_BACKLOG.md` for PRD-005 Phase 1 tasks

### Scope Overlap Resolution

| Overlapping Path             | Primary Owner | Secondary  | Resolution                                                                |
| ---------------------------- | ------------- | ---------- | ------------------------------------------------------------------------- |
| `engines/**` (runtime)       | `cli`         | `platform` | `cli` owns module boundaries & exports; `platform` owns shared internals  |
| `package.json` (deps)        | `cli`         | `devops`   | `cli` owns `files`, `exports`, `bin`, publish scripts; `devops` owns rest |
| `.github/workflows/publish*` | `cli`         | `devops`   | `cli` owns publish workflow logic; `devops` owns runner config & secrets  |
| `scripts/publish*`           | `cli`         | `devops`   | `cli` primary; `devops` owns CI integration                               |

### Handoff Chain

```
cli → testing    (test the packaged output, install-from-tarball tests)
cli → infra      (publish pipeline CI, registry credentials)
cli → docs       (CLI usage docs, --help text, README install instructions)
```
