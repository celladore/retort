The `.cursor/settings.json` and `.windsurf/settings.json` files are not orphans — `platform-syncer.mjs:syncEditorTheme` emits them every sync run (77 colors from "AgentKit Forge"). Root-cause is an oscillation in the scaffold engine that only fires locally: when the editor-theme outputs exist in `projectRoot`, `synchronize.mjs:617-638` short-circuits the whole writer call, so the files never reach `tmpDir` and `cleanStaleFiles` deletes them as orphans. CI never sees this because CI has no `previousManifest`. Filed as baton ticket `376cacd9-…` with both fix options (write existing content to tmpDir, or extend the carry-forward set in `scaffold-engine.mjs:354-367`).

**Renovate adapter for gh-bot-reader.** Wrote `~/repos/org-meta/skills/gh-bot-reader/adapter-renovate.md` (245 lines) as the canonical reference for **body-posting bots**. Distinct from the CodeRabbit adapter because Renovate uses PR body + conversation comments via REST, not GraphQL review threads. Documents:

- Author identification across the Renovate brands (`renovate[bot]`, `renovate-bot`, `mend-renovate[bot]`).
- REST-fetch pattern with `--paginate` for the comments endpoint.
- Severity heuristics on explicit Renovate markers (`⚠ Artifact update problem`, `Branch automerge failure`, `Edited/Blocked`, `## ⚠ Rebase failed`) and the rebase-loop signature (≥ 4 Renovate force-pushes within 24h, plus the `<!-- renovate-debug -->` `retryCount` cross-check).
- Status mapping that derives from `pullRequest.mergeable_state` / head-SHA comparison rather than `isResolved` flags (which don't exist for body-only findings).
- Field mapping for body and comment findings — synthetic `thread_id = 'pr-body-' + n` for body findings; no `file`/`line`.
- Body sanitisation rules — strip the package table when it isn't the only content, strip `<details>` blocks, strip the four Renovate HTML comments, strip the Mend footer.
- Known gotchas: edited-bodies-have-no-comment-trail, Mend.io rebrand, rebase-check checkbox is interactive (not a finding), monorepo false positives on the loop signature.
