## The Core Finding

Retort generated 38 agent personas into `.claude/agents/*.md` and **none of them was ever registrable**. Every file opened with an HTML comment instead of YAML frontmatter, so Claude Code scanned and skipped all 38.

Two consequences that were not obvious until traced:

1. **The task delegation protocol was role-play.** `orchestrate.md` specifies a task JSON lifecycle with `dependsOn`/`blockedBy` derivation, DFS cycle detection with SHA-256 cycle IDs, lock leasing with TTL, two-phase commit, and `HANDOFF_DEPTH_EXCEEDED` events. All of it ran inside a single main-thread context writing JSON files to itself. No second agent ever ran, so none of that concurrency machinery was exercised.
2. **The spec was far ahead of the emitter.** `accepts`, `depends-on`, `notifies`, `handoff-chain`, `decision-model`, `retry-policy`, `negotiation`, `lookahead`, `confidence` are all modelled in YAML and all rendered as prose. They described a runtime that did not exist.

The runtime capability was never the gap — Claude Code subagents already nest up to three layers by default. The gap was emission.

## What Was Done

**Emitter (Phases 1–2).** Agents now emit `name`, `description`, `model`, `color`, with guardrails derived from the `accepts` field that already classified task types: no write-capable type → `disallowedTools: Write, Edit, NotebookEdit`; a code-writing type → `isolation: worktree`. 14 agents get worktree isolation, 18 become structurally read-only.

**Verified live.** After sync, Claude Code registered `backend`, `security-auditor`, `test-lead` and 35 others as agent types mid-session, with read-only agents reported as _"All tools except Write, Edit, NotebookEdit"_. The derivation is enforced by the runtime, not merely written to a file.

## Traps Worth Knowing

**1. Sync in a worktree silently uses the wrong overlay.** `resolveOverlaySelection` falls back to the directory basename, which for a harness-created worktree is `agent-dispatch-capability-ebfc25`, not `retort` — so it lands on `__TEMPLATE__` and regenerates the whole repo with template defaults. The first sync produced **439 changed files**; with a `.agentkit-repo` marker it produced **62**. The tell was `last_updated: '' → '<date>'` on 415 files, because retort's overlay sets `syncDateMode: none` specifically to suppress that churn. `.agentkit-repo` is gitignored, so it must be recreated in every new worktree. Commit `a2bb7a29` only auto-creates it for `retort worktree create`.

**2. `managed` scaffold merge behaves differently in CI.** A hand-maintained ADR index survived sync locally because the scaffold cache marked the file user-edited. CI has no such cache, treated the file as pristine, overwrote it, and the drift check failed. **Local sync being clean does not prove CI drift will pass.**

**3. Templates under `docs/` are `scaffold: once`.** Fixing a template does not reach an existing repo's checked-in copy — that has to be fixed directly as well. Two of the six link fixes needed both.

**4. `sync-integration.test.mjs` is timing-flaky on slow machines.** Each test runs a full `runSync` (60–90s here). Across runs the failures were _non-overlapping_ — `--only mcp`/`--only windsurf` in one, `--overwrite`/`--force` in another — all pure duration overruns with no assertion output. Not logic failures. Treat CI as authoritative.

## Open Questions

- **Name collisions.** 38 agents with generic names (`backend`, `data`, `infra`) now occupy global agent-type space alongside plugin agents. Duplicate `name` values resolve by filesystem read order, which is not documented precedence. An `agent-name-prefix` setting is specced but not implemented.
- **Description-matching surface.** 38 dispatchable agents is a lot for automatic delegation to disambiguate. Consider emitting frontmatter only for agents that are actual delegation targets — those appearing in some `notifies` or `handoff-chain`.
