`prettier.test.mjs` fails locally on Windows against three files this PR does not

`core.autocrlf=true` checks hand-authored files out as CRLF while prettier defaults

## Real Pre-Existing Bug Found — Generated `.ps1` Files Do Not Parse on PowerShell 5.1

Surfaced by PSScriptAnalyzer output attached to a CodeRabbit comment
(`PSUseBOMForUnicodeEncodedFile`), and confirmed:

```text
powershell -File ./scripts/create-doc.ps1 …
Missing closing '}' in statement block or type definition.
```

Generated `.ps1` files are UTF-8 **without a BOM** and contain non-ASCII (`ℹ️`,
em-dashes). Windows PowerShell 5.1 decodes non-BOM files as ANSI, mangling the
multi-byte sequences and breaking string terminators — the file fails to parse
**entirely**, so every `.ps1` this repo generates is dead on 5.1. It parses clean
under pwsh 7.6.3.

**Pre-existing, not from this PR** — `origin/dev` and the pre-PR `6d2d4e6c`
version both fail with the same 3 parse errors under 5.1. This affects every
generated `.ps1`, so the fix belongs in the sync engine's file writer (emit a BOM
for non-ASCII `.ps1`), not in individual templates. **Not fixed here — needs its
own PR.** Windows PowerShell 5.1 is the default shell on Windows, so this is worth
prioritising.

All PowerShell verification in this session was therefore run under `pwsh`.
