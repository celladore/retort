## What Was Done

### PR #576 — `fix(scripts): derive history doc numbers from disk, not just the index`

Two commits:

1. `fix(scripts): derive history doc numbers from disk, not just the index` — six script files (three templates + three regenerated)
2. `fix(docs): renumber duplicate implementation history doc` — the rename and `.index.json`

**Numbering.** The next number came solely from the `sequences` counter in
`docs/history/.index.json`. Docs predating the index were never registered, so the
counter under-reported and issued numbers already taken on disk. A compounding
error: after use it advanced from its own stale value rather than from the number
actually issued, so it never caught up. Now
`max(index counter, highest NNNN- prefix on disk + 1)`, with the index still
written for the audit trail but no longer trusted alone. Index write corrected to
`Number(seqNum) + 1`.

**CHANGELOG link.** The caller passed `"$SUBDIR/$FILENAME"` — relative to
`docs/history/` — but `CHANGELOG.md` is at the repo root, so every link 404'd.
Fixed in `create-doc.sh`, **not** in `update-changelog.sh`, whose usage docs and
examples already specified the repo-root-relative form.

**PR reference.** Now rendered as a markdown link via the `githubSlug` template
variable, matching the convention already used in existing history docs. Falls
back to a bare `#123` when the slug is unset.

**`validate-numbering.sh`.** Widened from four subdirectories to six — `issues/`
and `lessons-learned/` are numbered the same way and previously went unchecked.
Dropped its unused per-subdir `TYPE` mapping (dead code).

**PowerShell parity.** `create-doc.ps1` carried every defect identically and was
fixed alongside.

## Two Deviations From the Brief

Both were verified before deviating, and both are documented in the PR body.

1. **`[#PR-Number]` was already working.** The brief reported it as left unfilled.
   A probe against the unmodified script emitted `**PR**: #999`. The real gap was
   the _form_ — a plain `#N` rather than the linked form used elsewhere — and that
   is what changed. `[Reviewer]`, `[Bug ID]`, `[Severity]`, and `[PR Title]` remain
   placeholders; none are derivable from a PR number.
2. **The renumber target `0002-` was already taken.** `implementations/` held
   `0002-` through `0008-`, so following the brief literally would have traded one
   duplicate for another. Used `0009-` — next free, and keeps the doc in date order
   after `0008-` (2026-03-17). No inbound links referenced the old filename
   (grepped markdown, JSON, YAML).

## Known Non-Issue — Do Not "Fix" This

`prettier.test.mjs` fails locally on Windows against three files this PR does not
touch: `.claude/plans/tui-entry-point.md`, `.claude/rules/agent-delegation.md`,
`.claude/rules/hookify.md`.

This is a `core.autocrlf=true` artifact. Those are hand-authored (non-generated)
files, so git checks them out with CRLF while prettier defaults to `endOfLine: lf`.
Sync-generated files are written by Node with LF, which is why only these three are
flagged. Running `prettier --write` on them produced a **zero-byte content diff** —
they are already correctly formatted. CI on Linux checks out LF and passes. Nothing
was committed for it.
