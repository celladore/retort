# Scaffold Management Guide

This guide explains how Retort manages generated files, how drift detection
works, and how to control scaffold behavior for your project.

## What Are Scaffold Modes?

Every template file in `.agentkit/templates/` can declare a **scaffold mode** that
controls whether the sync engine overwrites it on subsequent runs. There are three modes:

| Mode        | Behavior                                                     | Use Case                                   |
| ----------- | ------------------------------------------------------------ | ------------------------------------------ |
| **always**  | Always overwritten on every sync                             | Generated indexes (e.g. `docs/README.md`)  |
| **managed** | Smart regeneration — overwrites if pristine, preserves edits | Category READMEs, generated guides         |
| **once**    | Written once, never overwritten (default for `docs/`)        | User-owned content (PRDs, handoffs, specs) |

### How Modes Are Declared

Templates use YAML frontmatter to declare their mode:

```yaml
---
agentkit:
  scaffold: always
---
<!-- GENERATED by Retort ... -->
# My Template Content
```

The frontmatter is **stripped** during rendering — it never appears in the generated output.

Files without frontmatter inherit the default behavior based on their path:

- `docs/` → `once` (scaffold-once)
- `.vscode/` → `once`
- `.github/ISSUE_TEMPLATE/` → `once`
- AI tool configs (`.claude/`, `.cursor/`, etc.) → `always` (always regenerated)

## How Drift Detection Works

When a file uses `managed` mode, the sync engine compares what's on disk with what
was last generated:

1. **Compute disk hash** — SHA256 of the file currently on disk
2. **Look up manifest hash** — the hash stored in `.agentkit/.manifest.json` from the last sync
3. **Compare**:
   - **Hashes match** → file is pristine (untouched since last sync) → safe to overwrite
   - **Hashes differ** → user has edited the file → attempt three-way merge or skip

This means you can freely edit `managed` files. The sync engine will detect your changes
and preserve them.

## Three-Way Merge

When the sync engine detects that you've edited a `managed` file AND the template has
also changed, it attempts a **three-way merge** using `git merge-file`:

| Version          | Source                             | Description                             |
| ---------------- | ---------------------------------- | --------------------------------------- |
| **YOUR_EDITS**   | File on disk                       | Your current version with your edits    |
| **LAST_SYNC**    | `.agentkit/.scaffold-cache/<path>` | What sync last generated                |
| **NEW_TEMPLATE** | Newly rendered template            | What the updated template would produce |

### Clean Merge

If your edits and the template changes don't conflict, the merge succeeds silently.
You get both your custom content and the template updates combined.

### Conflict Markers

If there's a conflict, the file is written with standard conflict markers:

```markdown
<<<<<<< YOUR_EDITS
Content you added or modified
||||||| LAST_SYNC
What sync originally generated
=======
What the new template would produce

> > > > > > > NEW_TEMPLATE
```

Resolve these markers manually, just like a git merge conflict.

## How to Control Scaffold Behavior

### Template Frontmatter (Highest Priority)

Add to any template in `.agentkit/templates/`:

```yaml
---
agentkit:
  scaffold: always | managed | once
---
```

### project.yaml Overrides

In `.agentkit/spec/project.yaml`, you can override scaffold behavior for specific files:

```yaml
scaffoldOverrides:
  alwaysRegenerate:
    - docs/README.md # Force always-regenerate even if normally scaffold-once
  scaffoldOnce:
    - CLAUDE.md # Force scaffold-once even if normally always-regenerated
```

### CLI Flags (Overrides Everything)

```bash
pnpm --dir .agentkit agentkit:sync --overwrite  # Overwrite ALL files regardless of mode
pnpm --dir .agentkit agentkit:sync --force       # Same as --overwrite
```

### Priority Order

From highest to lowest:

1. `--overwrite` / `--force` CLI flag → overwrite everything
2. Template frontmatter `scaffold: always` → always regenerate
3. Template frontmatter `scaffold: managed` → regenerate if pristine (hash check)
4. Template frontmatter `scaffold: once` → never regenerate
5. `project.yaml` `scaffoldOverrides.alwaysRegenerate` list → force regenerate
6. `project.yaml` `scaffoldOverrides.scaffoldOnce` list → force once
7. Built-in path-based defaults (`docs/` = once, `.claude/` = always, etc.)

## Common Scenarios

### "I edited a generated README and want to keep my changes"

If the file is `managed`, your changes are automatically preserved. The sync engine
detects your edits via hash comparison and either merges them with template updates
or skips the file entirely.

### "I want to reset a file to the latest template"

Delete the file and run `pnpm --dir .agentkit agentkit:sync`. The file will be regenerated
from the template. Alternatively, use `--overwrite` to force-regenerate all files.

### "Sync shows CONFLICT markers in my file"

Resolve the conflict markers just like a git merge conflict. The labels tell you which
section is which:

- `YOUR_EDITS` — your changes
- `LAST_SYNC` — what sync last generated
- `NEW_TEMPLATE` — what the new template produces

### "I want my template edits upstreamed"

If you've made improvements to a generated file that would benefit the template:

1. Modify the template in `.agentkit/templates/`
2. Run `pnpm --dir .agentkit agentkit:sync`
3. Submit a PR to the retort repository

## Scaffold Cache

The directory `.agentkit/.scaffold-cache/` stores copies of generated content for
`managed` files. This serves as the merge base for three-way merges.

- **Gitignored** — not committed to version control
- **Auto-populated** — updated every time sync writes a managed file
- **Safe to delete** — if missing, sync falls back to skip-and-warn for edited files
- **Rebuilds automatically** — next sync recreates it for all managed files

### Clearing the Cache

```bash
rm -rf .agentkit/.scaffold-cache/
```

After clearing, the next sync will write fresh cache entries for all managed files.
Until then, edited managed files cannot be three-way merged (they'll be skipped instead).

## Sync Summary Output

After each sync, you'll see a scaffold summary showing what happened:

```
[agentkit:sync] Scaffold summary:
  - 1 file(s) always-regenerated
  - 8 managed file(s) regenerated (pristine)
  - 1 managed file(s) merged (user edits + template changes)
  - 0 managed file(s) with CONFLICTS
  - 0 managed file(s) preserved (user edits, no merge possible)
  - 45 scaffold-once file(s) skipped
```

## Post-Sync Formatting

The sync engine automatically runs Prettier on all generated files after writing them.
This ensures consistent formatting regardless of template output. The Prettier binary
from `.agentkit/node_modules/prettier/` is used, respecting the project's `.prettierrc`
and `.prettierignore` configuration.
