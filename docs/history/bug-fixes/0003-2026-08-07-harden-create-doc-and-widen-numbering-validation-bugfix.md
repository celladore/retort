# Harden create-doc and widen numbering validation Resolution - Historical Summary

**Completed**: 2026-08-07
**Bug ID**: n/a — reported directly, no tracking issue
**PR**: [#576](https://github.com/phoenixvc/retort/pull/576)
**Severity**: Low

## Problem Description

This work began as a fix for two recurring `scripts/create-doc.sh` defects —
colliding sequence numbers and 404'ing CHANGELOG links. **Those two fixes landed
independently on `dev` via [PR #573](https://github.com/phoenixvc/retort/pull/573)
while this branch was in flight**, so they are not this document's subject —
see PR #573 for that history.

What remained after merging `dev` are four smaller defects in the same code path
that #573 did not address:

1. **`validate-numbering.sh` checked only four of six numbered subdirectories.**
   `issues/` and `lessons-learned/` are numbered identically, so a duplicate in
   either passed CI silently. The guard was narrower than the thing it guarded.
2. **A corrupted `.index.json` aborted the run mid-way.** Sequence derivation
   tolerated an unreadable index, but the _update_ step called `JSON.parse`
   unguarded — so a malformed index crashed the script **after** the document had
   already been written, leaving no index entry and no changelog entry. The
   PowerShell variant was worse: `ConvertFrom-Json` ran _before_ the on-disk scan
   under `$ErrorActionPreference = 'Stop'`, so its documented tolerance never
   applied at all.
3. **The PR reference rendered as a bare `#123`**, not the
   `[#123](https://github.com/org/repo/pull/123)` form used across existing
   history docs — so every generated doc needed the field rewritten by hand.
4. **`sequences.implementation` was left at `1`** after #573 renumbered the
   duplicate to `0009-`. Harmless given the disk scan, but the audit trail was
   lying about what was on disk.

## Root Cause Analysis

Items 1 and 4 are incomplete-cleanup: the numbering fix corrected the _issuing_
side without correspondingly widening the _detecting_ side or reconciling the
counter it had just superseded.

Item 2 is an inconsistency introduced by the numbering fix itself. Making
derivation fault-tolerant without making the update step fault-tolerant left the
script strictly worse in one respect: it now proceeded far enough to write a
document before failing, where previously it would have failed immediately.

Item 3 is a missing-affordance rather than a fault — `githubSlug` was already
available as a template variable and simply was not used.

## Solution Implemented

`validate-numbering.sh` now iterates all six numbered subdirectories, and its
unused per-subdir `TYPE` mapping (dead since the check is purely filename-based)
is removed.

Both `create-doc` variants wrap index parsing in `try`/`catch` and rebuild the
index rather than aborting, guarding that `sequences` exists before writing to
it. Rebuilding is the right failure mode here: the numbering is already derived
from disk, so a lost index costs only history, not correctness.

The PR reference is rendered through the `githubSlug` template variable, with a
guard for the unresolved-placeholder case so adopter repos without a slug fall
back to a bare `#123`.

### Code Changes

Source of truth is `.agentkit/templates/scripts/`; the `scripts/` copies are
regenerated by `pnpm --dir .agentkit retort:sync`.

- **`.agentkit/templates/scripts/validate-numbering.sh`**: scans
  `issues/` and `lessons-learned/` in addition to the original four; dead `TYPE`
  mapping removed.
- **`.agentkit/templates/scripts/create-doc.sh`**: `try`/`catch` around both the
  derivation read and the update read, the latter rebuilding the index and
  warning on stderr; `sequences` guarded before write; PR reference rendered via
  `GITHUB_SLUG`.
- **`.agentkit/templates/scripts/create-doc.ps1`**: same, using
  `try`/`catch` around `ConvertFrom-Json` and `Add-Member` to restore a missing
  `sequences` object.
- **`scripts/{create-doc.sh,create-doc.ps1,validate-numbering.sh}`**: regenerated.
- **`docs/history/.index.json`**: `sequences.implementation` corrected `1` → `10`.

### Regression Testing

`validate-numbering.sh` runs in CI via `documentation-quality.yml` and
`documentation-validation.yml`; its widened scope means duplicates in `issues/`
and `lessons-learned/` now fail the build rather than passing silently.

## Impact Assessment

Anyone running `create-doc.sh`, which `CLAUDE.md` makes mandatory after
significant work. Before this change every generated document needed its `**PR**`
field rewritten by hand, and a corrupted index produced a confusing half-completed
run. Neither was severe — hence Low — but both were routine friction.

## Prevention Measures

The generalisable point: **when you make one side of a check fault-tolerant, check
the other side too.** The corrupted-index gap existed precisely because tolerance
was added to derivation and not to the update that follows it — the comment
claimed a robustness the code did not deliver.

Similarly, widening the issuing logic without widening the validating logic left
a detection blind spot. A fix to a numbering scheme should touch both.

## Lessons Learned

- **Duplicate work is the headline lesson.** #573 fixed the same two defects on
  `dev` from a parallel session, discovered only when this PR went `CONFLICTING`.
  Checking for in-flight work on the same file — via `task_check`, open PRs, or
  `git log origin/dev` — before starting would have cost seconds and saved most of
  this branch. The merge was resolved with hunk-level `-X ours` after confirming
  each conflicting block was a superset of dev's, which preserved #573's
  `update-changelog.sh` markdownlint fix that this branch lacked.
- The bot review (Copilot) found the corrupted-index inconsistency across all four
  affected files. It was correct, and the PowerShell instance was worse than
  reported — worth verifying a bot finding rather than accepting its severity.
- One originally reported symptom did not reproduce: `[#PR-Number]` was already
  being substituted. Probing the unmodified script first prevented a fix to
  working code and redirected effort to the actual gap.
- Both defects existed in the PowerShell variant. Any `.sh` template change in
  this repo should check its `.ps1` sibling.
