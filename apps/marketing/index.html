How it works

Spec in, generated configs out

Four steps, all of them repeatable. Sync is idempotent, so running it twice changes nothing and CI can fail the build when a generated file has drifted from the spec.

1 .agentkit/spec/*.yaml

Describe

project.yaml, teams.yaml, commands.yaml and rules.yaml hold the facts about your repo — stack, owners, scripts, conventions.

2 retort validate

Validate

The spec is schema-checked before anything is written, so a typo surfaces as an error instead of a broken agent config.

3 retort sync

Sync

One pass renders every enabled target to its native location and format. Same spec, same output, every time.

4 retort check

Commit & guard

Generated files are committed like any other artifact. Drift detection in CI catches hand-edits before they diverge.

Quick start

Four commands from empty repo to synced configs

No global install, no config server, nothing to host. The spec and the generated files live in your repository.

01Scaffold the four spec files with sensible defaults detected from your repo.
02Edit the YAML, then validate before generating anything.
03Sync, review the diff, commit the generated configs.
04Add retort check to CI for quality gates, and diff sync output there to catch drift before it merges.
